# ditl — декларации ITL 002 и ITL 004 в браузере

Формы с валидацией для двух деклараций юридических лиц, DGITL Sector 2 București:

- **ITL 002** (Model 2016, Anexa nr. 2) — налог на здания;
- **ITL 004** (Model 2016, Anexa nr. 4) — налог на землю (например, доля участка под зданием с парковкой).

Документ собирается из шаблона [Typst](https://typst.app) и данных формы. Результат —
один самодостаточный файл `.typ` (данные + шаблон + логотип), который можно скачать
и собрать в PDF локально, или превратить в PDF прямо в браузере.

- Всё выполняется в браузере: нет backend'а, базы данных и аналитики.
- Данные никуда не отправляются — в production-сборке это закреплено CSP
  (`connect-src 'self'`, `form-action 'none'`, см. `vite.config.ts`).
- Компилятор Typst для браузера (WASM, ≈ 28 МБ, по сети ≈ 11 МБ) загружается только
  по кнопке на экране результата; дальше браузер берёт его из кэша.
- Черновики автосохраняются в `localStorage` этого браузера и переживают перезагрузку.

Стек: React + TypeScript + Zod (через react-hook-form), Typst (typst.ts в браузере),
Vite, Vitest. Хостинг — GitHub Pages.

## Окружение

```sh
direnv allow        # или: nix develop — Node и Typst CLI
npm install
npm run dev         # http://localhost:5173
```

| Команда           | Что делает                                                  |
| ----------------- | ----------------------------------------------------------- |
| `npm run dev`     | dev-сервер                                                  |
| `npm test`        | тесты валидаторов, схем, шаблонов (компиляция Typst) и форм |
| `npm run build`   | проверка типов + сборка в `dist/`                           |
| `npm run preview` | локальный просмотр production-сборки (с CSP)                |

## Как устроено

```
src/
  forms.ts              реестр деклараций: схема, разделы, шаблон, данные для печати, имя файла
  form/common.ts        общие части схем: адрес, реквизиты фирмы, документ подписанта, CUI/CNP/IBAN
  form/validators.ts    CUI, CNP, IBAN (контрольные цифры), суммы в леях, диакритика ș/ț
  form/fields.tsx       поля формы, адресный блок, приложения
  form/sections.tsx     сворачиваемые разделы: статус, сводка, автосворачивание
  itl002/, itl004/      schema.ts — Zod-схема; sections.ts — разделы; Fields.tsx — поля;
                        print.ts — данные для шаблона; sample.ts — тестовые данные
  drafts/               черновики в localStorage и панель черновиков
  typst/                шаблоны и сборка .typ (см. ниже)
  output/Result.tsx     экран результата: «Descarcă .typ», кнопка загрузки компилятора
  output/PdfView.tsx    ленивый чанк: компилятор Typst, предпросмотр и «Descarcă PDF»
  assets/fonts/         Liberation Sans/Serif (OFL), метрически совместимы с Arial/Times бланков
```

### Шаблоны Typst

```
src/typst/
  itl002.typ, itl004.typ   шаблоны; текст — по бланкам templates/*.docx
  common.typ               общее: пустое место с точками, чекбокс, шрифты, нумерация страниц
  embed.typ                base64 → bytes (логотип внутри .typ)
  samples/*.json           данные для правки шаблонов через CLI
  bundle.ts                склейка в один .typ: данные (литерал Typst) + common + шаблон + логотип
  compiler.ts              typst.ts в браузере
```

Шаблон получает данные уже в печатном виде (даты «31.01.2024», суммы «1.250.000,00»);
форматирование — в `print.ts` на стороне TS. Чтобы править шаблон с живым предпросмотром:

```sh
typst watch --font-path src/assets/fonts src/typst/itl004.typ
```

Без `--input data=…` шаблон берёт `samples/itl004.json`. Тест проверяет, что эти JSON
совпадают с тем, что печатает приложение, — после изменения `print.ts` или тестовых
данных их нужно обновить.

Отличия от бумажных бланков (сознательные): раскладка своя; в ITL 004 печатаются только
заявленные участки и строки таблицы, из «dobândit/închiriat/…» — только выбранный
вариант; в обоих — только заполненные приложения. Подписи и печать ставятся от руки.

### Компилятор в браузере и CSP

typst.ts 0.7.0 (внутри Typst 0.14) закреплён точной версией. Тесты компилируют .typ
нативной сборкой того же движка (`@myriaddreamin/typst-ts-node-compiler`).

Под CSP без `'unsafe-eval'` пришлось обойти два места, где typst.ts создаёт функции из строк:

- штатный `loadFonts` — вместо него свой загрузчик шрифтов из байтов (`src/typst/compiler.ts`);
- wasm-bindgen-обвязка — плагин `typstWithoutEval` в `vite.config.ts` подставляет готовые
  функции для известных тел; если обвязка в новой версии изменится, сборка остановится.

Для WebAssembly в CSP добавлен `'wasm-unsafe-eval'`.

### Разделы формы

Форма сплошная, разделена на блоки. У каждого заголовка — статус: «De completat»,
«N câmpuri de corectat» или «✓ Gata». Раздел без ошибок сворачивается, когда фокус
переходит в другой раздел, и показывает сводку; кликом по заголовку его можно
открыть. Порядок заполнения не навязывается. При отправке с ошибками разделы
с ошибками раскрываются, фокус встаёт на первое ошибочное поле.

### Черновики

Одна декларация — одно здание (ITL 002) или до пяти участков (ITL 004), поэтому
черновиков может быть несколько. Все хранятся в `localStorage` под ключом
`ditl.drafts.v1` (тип декларации и сырые значения полей) и никуда не отправляются.

- Черновик создаётся при первом вводе; пустая форма его не создаёт.
- Запись — через 500 мс после последнего изменения, а также при переключении
  черновика, скрытии вкладки (`visibilitychange`/`pagehide`) и размонтировании.
- При загрузке страницы открывается последний активный черновик; готовые разделы свёрнуты.
- «Declarație nouă: ITL 002 / ITL 004» — пустая форма, прежний черновик остаётся в списке.
- «Același contribuabil: ITL 002 / ITL 004» — новый черновик с данными той же фирмы.
  Внутри одного типа переносится всё, кроме объекта декларации (здания или участков)
  и приложений; между ITL 002 и ITL 004 — реквизиты фирмы и документ подписанта.
- «Ciornele mele» — список с типом декларации: открыть или удалить.
- Черновики, сохранённые до появления ITL 004, открываются как ITL 002.
- Если схема поменялась, старый черновик дополняется значениями по умолчанию;
  поля, которых больше нет или с неверным типом, отбрасываются (`withDefaults`).
- Хранилище перечитывается перед каждой записью, так что две вкладки с разными
  черновиками друг друга не затирают. Один черновик в двух вкладках — побеждает
  последняя запись.

### Правила проверки

Общие:

- **CUI** — с проверкой контрольной цифры; префикс `RO` и пробелы убираются.
- **Cod poștal** — 6 цифр, если страна — România.
- **Comunicare exclusiv prin e-mail: DA** требует адрес почты.
- Суммы и площади принимаются как `1.250.000,50`, `1250000.50`, `1 250 000` и печатаются
  в румынском формате.
- Текст нормализуется: NFC, `ş/ţ` с седилью → `ș/ț` с запятой.

ITL 002:

- Для юрлица код фискальной идентификации совпадает с CUI, поэтому он печатается
  в обе строки («Codul de identificare fiscală» и «Codul unic de identificare»).
- **Împuternicit** (раздел II) — необязателен; если отмечен, нужны имя, фамилия
  и CNP или CUI (тоже с контрольной цифрой).
- **Индикаторы стоимости (раздел IV)**: показываются и печатаются только колонки,
  подходящие типу здания (rezidențial / nerezidențial / обе для mixtă); нужна хотя бы
  одна стоимость, и у каждой стоимости — дата документа.

ITL 004:

- Обязательны имя подписанта и его документ; **CNP** и **IBAN** необязательны,
  но если указаны — с проверкой контрольных цифр.
- От одного до пяти участков; у каждого — дата и акт, форма получения, адрес,
  intravilan/extravilan и площадь хотя бы одной категории использования.
- «Județul/Sectorul» адреса печатается как в тексте бланка: «Sector 2» → județ
  București, sector 2.

## Деплой на GitHub Pages

В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
Workflow `.github/workflows/deploy.yml` на каждый push в `main` прогоняет тесты,
собирает и публикует `dist/`. `base: './'` в Vite — сборка работает под любым
именем репозитория.
