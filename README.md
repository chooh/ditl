# ditl — декларации ITL 002 и ITL 004 в браузере

Одна форма с валидацией — «досье» юридического лица на один объект, — из которой собираются
декларации для DGITL Sector 2 București:

- **ITL 002** (Model 2016, Anexa nr. 2) — налог на здание;
- **ITL 004** (Model 2016, Anexa nr. 4) — налог на землю под ним.

В досье: фирма, подписант, акт приобретения и объект — здание и земля под ним. Декларации
подаются по объекту, поэтому одно досье — один объект; следующий объект той же фирмы (или
того же договора — квартира и парковка) — новое досье с перенесёнными данными (см. «Черновики»).
Каждый документ собирается из шаблона [Typst](https://typst.app) и данных досье. Результат —
самодостаточные файлы `.typ` (данные + шаблон + логотип), которые можно скачать
и собрать в PDF локально, или превратить в PDF прямо в браузере.

- Всё выполняется в браузере: нет backend'а, базы данных и аналитики.
- Данные никуда не отправляются — в production-сборке это закреплено CSP
  (`connect-src 'self'`, `form-action 'none'`, см. `vite.config.ts`).
- Компилятор Typst для браузера (WASM, ≈ 28 МБ, по сети ≈ 11 МБ) — отдельный чанк: начинает
  загружаться на шаге проверки, а «Generează documentele» сразу собирает оба PDF; дальше
  браузер берёт компилятор из кэша. Не загрузился — экран результата предлагает повторить.
- Черновики автосохраняются в `localStorage` этого браузера и переживают перезагрузку.

Стек: React + TypeScript + Zod (через react-hook-form), интерфейс на
[Carbon Design System](https://carbondesignsystem.com) (`@carbon/react`), Typst (typst.ts
в браузере), Vite, Vitest. Хостинг — GitHub Pages.

## Окружение

```sh
direnv allow        # или: nix develop — Node и Typst CLI
npm install
npm run dev         # http://localhost:5173
```

| Команда           | Что делает                                                  |
| ----------------- | ----------------------------------------------------------- |
| `npm run dev`     | dev-сервер                                                  |
| `npm test`        | тесты валидаторов, схем, шаблонов (компиляция Typst) и форм |
| `npm run build`   | проверка типов + сборка в `dist/`                           |
| `npm run preview` | локальный просмотр production-сборки (с CSP)                |

### Шаблоны Typst

```
src/typst/
  itl002.typ, itl004.typ   шаблоны; текст — по бланкам templates/*.docx
  common.typ               общее: пустое место с точками, чекбокс, шрифты, нумерация страниц
  embed.typ                base64 → bytes (логотип внутри .typ)
  samples/*.json           данные для правки шаблонов через CLI
  bundle.ts                склейка в один .typ: данные (литерал Typst) + common + шаблон + логотип
  compiler.ts              typst.ts в браузере
```

Шаблон получает данные уже в печатном виде (даты «31.01.2024», суммы «1.250.000,00»);
форматирование — в `print.ts` на стороне TS. Чтобы править шаблон с живым предпросмотром:

```sh
typst watch src/typst/itl004.typ
```

Шрифты в dev-шелле подхватываются из `TYPST_FONT_PATHS` (задан в `flake.nix`): macOS
не поставляет Liberation, и без этого typst CLI молча откатывается на Times New Roman,
то есть даёт не тот же результат, что браузер. Вне шелла — `--font-path src/assets/fonts`.

Без `--input data=…` шаблон берёт `samples/itl004.json`. Тест проверяет, что эти JSON
совпадают с тем, что печатает приложение, — после изменения `print.ts` или тестовых
данных их нужно обновить.

Ключи данных шаблонов — румынские, как графы бланков; `print.ts` переводит в них
английские поля досье.

Отличия от бумажных бланков (сознательные): раскладка своя; в ITL 004 печатается только
пункт «1. începând cu data de…» и одна строка таблицы — участок под объектом досье (шаблон
умеет и несколько), из «dobândit/închiriat/…» — только выбранный вариант; в обоих — только
заполненные приложения. Подписи и печать
ставятся от руки.

### Компилятор в браузере и CSP

typst.ts 0.7.0 (внутри Typst 0.14) закреплён точной версией. Тесты компилируют .typ
нативной сборкой того же движка (`@myriaddreamin/typst-ts-node-compiler`).

Под CSP без `'unsafe-eval'` пришлось обойти два места, где typst.ts создаёт функции из строк:

- штатный `loadFonts` — вместо него свой загрузчик шрифтов из байтов (`src/typst/compiler.ts`);
- wasm-bindgen-обвязка — плагин `typstWithoutEval` в `vite.config.ts` подставляет готовые
  функции для известных тел; если обвязка в новой версии изменится, сборка остановится.

Для WebAssembly в CSP добавлен `'wasm-unsafe-eval'`.

### Населённые пункты (SIRUTA)

В каждом адресе — фирмы, адресе для переписки, домициле подписанта и адресе объекта —
есть поиск «Caută localitatea» по справочнику SIRUTA (INS). Выбор заполняет графы
«Județul» (у адреса объекта её нет), «Municipiul / orașul / comuna» и «Satul / sectorul»,
а под поиском показывает, что это за пункт: «Sector al municipiului București»,
«Municipiu, județul Alba», «Sat aparținând comunei Ciugud, județul Alba». Так видно, что
идёт в «oraș», а что в «sector» или «sat»:

| Выбрано               | Județul   | Municipiul / orașul / comuna | Satul / sectorul |
| --------------------- | --------- | ---------------------------- | ---------------- |
| București, Sector 2   | București | București                    | Sector 2         |
| mun. Alba Iulia       | Alba      | Alba Iulia                   | —                |
| Drâmbar, com. Ciugud  | Alba      | Ciugud                       | Drâmbar          |

Графы остаются редактируемыми (адрес за границей, расхождения в написании); если
значения не находятся в SIRUTA, поиск предупреждает, но не блокирует.

RENNS (Registrul Electronic Național al Nomenclaturilor Stradale, ANCPI) подключить
нельзя: публичного API нет — веб-сервисы ANCPI выдаёт учреждениям по протоколу, — да
и запрос отправлял бы адрес третьей стороне, а CSP разрешает только свой origin.
Поэтому справочник встроен в сборку и улиц не содержит.

Справочник — отдельный чанк (≈ 300 КБ, по сети ≈ 85 КБ), загружается при первом
показе адреса. Данные — «SIRUTA_s1 2026» с [data.gov.ro](https://data.gov.ro/dataset/siruta_s1-2026)
под CC BY 4.0 (атрибуция — в футере). Обновить:

```sh
node scripts/siruta.ts siruta_s1_2026.csv   # CSV с data.gov.ro → src/address/siruta.json
```

Скрипт приводит имена к обычному написанию («VALEA LUI MIHAI» → «Valea lui Mihai»,
ş/ţ → ș/ț) и сохраняет иерархию județ → UAT → localitate с кодами TIP.

### Разделы формы

Форма сплошная, разделена на блоки. У каждого заголовка — статус: «De completat»,
«N câmpuri de corectat» или «✓ Gata». Раздел без ошибок сворачивается, когда фокус
переходит в другой раздел, и показывает сводку; кликом по заголовку его можно
открыть. Порядок заполнения не навязывается. При отправке с ошибками разделы
с ошибками раскрываются, фокус встаёт на первое ошибочное поле.

### Черновики

Черновик — это досье целиком. Все черновики хранятся в `localStorage` под ключом
`ditl.dossiers.v1` (сырые значения полей и разделы, подтверждённые кнопкой «Continuă»)
и никуда не отправляются. Черновики
отдельных деклараций ITL 002 / ITL 004 (ключ `ditl.drafts.v1`, до перехода на досье)
не переносятся и удаляются при первой загрузке.

- Черновик создаётся при первом вводе; пустая форма его не создаёт.
- Запись — через 500 мс после последнего изменения, а также при переключении
  черновика, скрытии вкладки (`visibilitychange`/`pagehide`) и размонтировании.
- При загрузке страницы открывается последний активный черновик — на первом неготовом
  разделе (готов — без ошибок и подтверждён «Continuă»), а если готовы все, на проверке.
- «Dosar nou» — пустая форма, прежний черновик остаётся в списке.
- «Dosar nou pentru această firmă» — новый черновик с реквизитами фирмы, подписантом
  и подписями; акт, объект и приложения не переносятся.
- «Dosar nou pentru această firmă și contractul» — то же плюс акт приобретения, а у объекта —
  адрес дома (улица, номер, блок, подъезд, населённый пункт), intravilan, ранг и зона: для
  следующего объекта того же договора. Этаж, квартира, стоимость, доля и площадь — пустые.
- «Ciornele mele» — список: открыть или удалить.
- Если схема поменялась, черновик дополняется значениями по умолчанию;
  поля, которых больше нет или с неверным типом, отбрасываются (`withDefaults`).
- Хранилище перечитывается перед каждой записью, так что две вкладки с разными
  черновиками друг друга не затирают. Один черновик в двух вкладках — побеждает
  последняя запись.

### Правила проверки

- **CIF** и **CUI** фирмы — отдельные поля, оба обязательны, с проверкой контрольной цифры.
  В CIF префикс `RO` (плательщик НДС) сохраняется, в CUI убирается; пробелы убираются в обоих.
- **CNP** подписанта и **IBAN** фирмы — с проверкой контрольных цифр, если указаны;
  CNP обязателен, если подписант — împuternicit.
- **Cod poștal** — 6 цифр, если страна — România.
- **Comunicare exclusiv prin e-mail: DA** требует адрес почты.
- **Документ подписанта**: дата выдачи (`issuedOn`) не в будущем; срок действия
  (`validTill`) необязателен (пусто — бессрочный), но если указан — позже даты выдачи
  и не раньше даты деклараций. В данных досье обе даты — `Date`.
- **Акт**: номер, дата, форма приобретения; «alte modalități» требует уточнения.
  «Data dobândirii» необязательна — по умолчанию это дата акта.
- **Объект**: улица и населённый пункт; у здания — тип и хотя бы одна
  стоимость (в таблице a)–e) — только колонки, подходящие типу здания, у каждой
  стоимости — дата документа); у земли — intravilan/extravilan и площадь хотя бы
  одной категории.
- Суммы и площади принимаются как `1.250.000,50`, `1250000.50`, `1 250 000` и печатаются
  в румынском формате.
- Текст нормализуется: NFC, `ş/ţ` с седилью → `ș/ț` с запятой.

Как поля досье попадают в декларации:

- В ITL 002 CIF и CUI печатаются в свои строки («Codul de identificare fiscală»
  и «Codul unic de identificare»); в ITL 004 есть только CIF. Имена файлов — по CUI.
- Раздел II ITL 002 («Împuternicit») заполняется подписантом, только если он
  împuternicit; у законного представителя раздел пустой. В ITL 004 подписант —
  «Subsemnatul…», а если не указан Director P.J., под подписью печатается он же.
- Телефон и факс фирмы в ITL 002 — в одной графе «Numărul tel./fax».
- В ITL 002 согласие «Sunt de acord… exclusiv la adresa de poștă electronică» (DA/NU) стоит в одной строке
  с телефоном и e-mail фирмы, а ниже — две строки адресов с подписями: «Adresa sediului social»
  и «Adresa de corespondență».
- Адрес объекта: в графе «Localitate/sector» ITL 002 — «București, Sector 2»; в пунктах
  участков ITL 004 — строкой, как в шапке (см. ниже): «un teren situat în municipiul
  București, sectorul 2, Șos. Mihai Bravu nr. 200». Județ у объекта не спрашивается, поэтому
  при одноимённых пунктах в разных уездах печатаются только названия.
- Адрес фирмы и подписанта в ITL 002: «Localitatea» — municipiul/orașul/comuna (у села —
  «Drâmbar, Ciugud»), «Județul/Sectorul» — сектор у Бухареста («Sector 2»), иначе județ.
  У адреса для переписки на бланке одна графа — туда идёт всё: «București, Sector 2»,
  «Drâmbar, Ciugud, jud. Alba».
- В шапке ITL 004 у фирмы два адреса — «cu sediul social în…» и «cu adresa de corespondență în…»
  (второй — только если заполнен), а согласие «Sunt de acord ca actele administrative fiscale…»
  с чекбоксом идёт в скобках сразу за адресом e-mail; без e-mail не печатается и согласие.
- В шапке ITL 004 домициль подписанта и адреса фирмы (и адреса участков) печатаются строкой, без подписей бланка
  «municipiul/orașul/comuna», «satul/sectorul» и без «România»: тип пункта берётся из SIRUTA —
  «municipiul București, sectorul 2, Str. Lizeanu nr. 21, …», «municipiul Brașov, județul Brașov, …»,
  «satul Drâmbar, comuna Ciugud, județul Alba, …». «str.» добавляется, только если в улице
  нет своего типа («Bd.», «Șos.», «Str.»…). Пункта нет в SIRUTA или адрес за границей —
  печатаются только названия.
- Сектор, записанный в графу «Județul» (так было в черновиках до SIRUTA), переносится
  в «Satul / sectorul»: «Sector 2» → județ București, sector 2.
- Приложения — один список (до девяти, как строк на бланке ITL 002), в обеих декларациях.

## Лицензия шрифтов

Liberation Sans/Serif 2.1.5 — © 2012 Red Hat, Inc. под [SIL Open Font License 1.1]
(полный текст: `public/LICENSE-Liberation.txt`, FAQ: <https://openfontlicense.org>).

Сборка раздаёт сами `.ttf` (`src/typst/compiler.ts` импортирует их через `?url`), а OFL
требует прикладывать к каждой распространяемой копии шрифта копирайт и текст лицензии —
поэтому лицензия лежит в `public/` и на неё ссылается футер страницы. При добавлении или
замене шрифтов это условие нужно выполнить заново.

Интерфейс набран IBM Plex Sans/Mono — © 2017 IBM Corp., тоже под OFL 1.1 (`public/LICENSE-IBM-Plex.txt`).
Carbon по умолчанию берёт `.woff2` из пакета `@ibm/plex` (`$font-path` в `src/styles.scss`), и Vite
кладёт их в сборку: CSP пускает шрифты только со своего origin, CDN IBM не используется.

На сгенерированные PDF лицензия не распространяется: OFL прямо исключает документы,
созданные с помощью шрифта. Встраивание шрифта в PDF разрешено.

[SIL Open Font License 1.1]: https://openfontlicense.org

## Деплой на GitHub Pages

В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
Workflow `.github/workflows/deploy.yml` на каждый push в `main` прогоняет тесты,
собирает и публикует `dist/`. `base: './'` в Vite — сборка работает под любым
именем репозитория.
